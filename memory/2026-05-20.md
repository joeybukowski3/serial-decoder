# 2026-05-20

- Fixed ambiguous repeating-year handling for serial decodes, focused on LG appliance serials such as `412TATG1H105`.
- Root cause: ambiguous serial results still flowed through `computeEstimatedAge()`, which picked the newest valid cycle year and surfaced a false single-year answer.
- Refactored serial narrowing in `script.js` into a shared model-evidence path used by both the initial decode flow and the `Narrow the Date` button.
- Added a small request cache + in-flight dedupe for model-based narrowing, removed the old candidate-years text from the lookup query, and added a timeout fallback so refinement does not hang indefinitely.
- UI behavior now hides estimated age for multi-year serial results until the model/context narrows the candidates to a single year.
- Added a local LG appliance model seed (`WM3470HWA` -> 2014 midpoint evidence) so the 2014 narrowing case is reproducible without relying on a generic AI-only response.
- Updated regression coverage for the LG ambiguous-year path, successful 2014 narrowing, and unresolved/unknown model behavior.
- Follow-up fix: the model number could still be ignored because `decodeSerial()` read from stored category state instead of the live `#modelNumber` field. The field binding also only attached when the input was newly created.
- Resolved by making the DOM model field the source of truth via `getCurrentSupplementalModelValue()` and always binding existing `#modelNumber` inputs before use.
- Follow-up fix 2: Frigidaire `FEFL79DBB` was still unresolved because the shared narrowing path had no model-era evidence to use. Added a local model-age seed for that range family and updated refine-note rendering so a successful refine replaces the ambiguous-cycle note instead of leaving the original unresolved message in place.
- Follow-up fix 3: added client-side model evidence fallback in `script.js` for known repeating-cycle cases so upfront decode and refine still narrow when `/api/age-lookup` is unavailable or returns no usable model-era signal.
- Follow-up fix 4: hardened the initial `decodeSerial()` async path so model-year narrowing can never strand the UI in loading or block result rendering. If the shared narrowing resolver throws, times out, or returns no confident match, the serial-only result now renders with a fallback note instead of hanging.
- Extended shared model-era narrowing so it filters repeating-cycle candidate years against model-era ranges before choosing a final year when there is no explicit estimated year conflict. This makes the same resolver work for LG and Whirlpool upfront searches and for the later `Narrow the Date` flow.
